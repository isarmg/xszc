# 维护应用数据

应用正常使用从[日常使用](usage.md)进入；登录、网络、权限和签名错误按[排查问题](troubleshooting.md)处理。本页用于判断队列和私有文件的用途。

日期显示、图库日/月分组及日期筛选统一为 UTC，UTC 的一个日范围为 24 小时。原始媒体时间戳按同一时间点使用，不从设备所在地区重新解释；后台调度仍交给系统，速率和运行预算仍使用单调计时。

## 本地数据

| 数据 | 所有者与允许操作 | 删除影响 |
| --- | --- | --- |
| 系统照片库原始照片/视频 | 由系统照片库和用户管理；客户端只读选择结果 | 客户端清理、卸载和重配均不得删除原件 |
| 宿主导出的临时源文件 | 平台层为一次准备过程导出；仅在确认没有 job 引用后清理 | 仍被引用时删除会使重试无法重新准备 |
| `prepared/` 上传分块 | Rust 队列按 job/part 管理；由成功确认或明确取消流程回收 | 手工删除会破坏待传任务及恢复证据 |
| 队列 SQLite | Rust 核心唯一拥有任务、分片、回执和绑定状态 | 删除会丢失进度、去重与完成记录，不能称为“清缓存” |
| 设备凭据 | Android 私有配置或 iOS Keychain | 删除后必须用当前实例授权码重新配对 |
| 图库预览缓存 | 可由应用重建，与上传回执独立 | 可清理，但不能据此改变队列状态 |

任何清理前先记录 job ID、队列状态和对应路径，仅使用产品提供的批次取消/完成记录清理入口。没有可证明的引用
关系时保留数据；“清缓存重试”不是身份、队列或 prepared parts 的恢复方法。



## 重试与恢复

到期的 `retry_wait` 任务若已有 `prepared_json`，会复用落盘分块。尚未准备完成的任务才重新读取源文件。准备中断留下的未引用代次，会在同任务后续准备成功时回收；排障时保留整个待传任务的证据。

“清空浏览缓存”适合释放可重建的图库图片。应用数据、队列数据库和已准备分块保存未完成任务，手工清除会丢失进度。要停止某次备份，使用传输页的批次取消；暂时停用应用使用账户退出。

## 本地数据库操作中断

Rust 核心的连接锁若因操作 panic 中毒，后续读取、入队、上传状态变更、图库或批次变更均返回 `StateLockPoisoned`。宿主应关闭当前 session 并重新打开本地数据库；继续使用该 session 不会越过锁失败。未提交 SQLite 事务会回滚，重开后按已验证的当前记录恢复，不把中断内存当作可继续的状态。


软件发行号与持久合同分别校验：当前软件为 1.1.3，应用版本为 1.0.0，移动 JSON revision 与 SQLite revision 均为 2，epoch `xszc-mobile-v1` 与 ABI 1 保持。移除无消费者的 `source_aliases` 并新增永久上传拒绝标记 `jobs.retry_blocked` 后严格校验新的 schema hash；旧 revision 1 数据库保留原位并明确拒绝打开，不迁移、不删除、不静默重置。请在采用本轮代码前确认旧设备队列已处理；旧库需要独立保存，不能按“清缓存”操作删除。


## 凭据和退役

怀疑设备凭据泄露时，先退出以停止任务，再请管理员轮换该实例授权码，并在设备上重新登录。轮换后旧 Token 失效，同实例队列按身份核验后继续使用。

卸载影响和远端授权处理见[安装指南](platform-setup.md)。正式发行与平台验收见[构建与测试](development.md#发布验证)。

## 当前移动操作

手动照片菜单显示“整个批次”和项目总数，取消/重试均需确认。长按上传标题可查看“已取消批次”并恢复未完成项目；已完成原件不会重复上传。长按上传/下载标题可清除已完成手动批次/下载列表记录，原件和上传回执保留。

上传的永久 HTTP 错误不自动重试；临时错误遵守服务器 `retryable` 与 `Retry-After`，等待时间写入队列。配套服务器必须接受 16 MiB 移动分块（配置范围 16–64 MiB）和最多 1 MiB/4096 块 manifest。

云图库筛选提供归档状态与标签。恢复确认只承诺主资源，Live Photo 配对视频和 RAW 等附加资源不会完整重建。
