# xszc 备份、图库与验收

本文描述 Android、iOS 和共享 Rust 核心的当前行为、配套服务端接口及验证入口。
应用发行版本为 `1.1.4`，移动状态契约版本为 `1.0.0`。

## 手动备份与云端浏览

| 要求 | 实现 |
|---|---|
| 四个主页面 | 本地、云端、传输、设置；长期自动备份策略独立保存，新用户默认关闭自动备份。两端均提供照片/视频类型开关；两端备份开关和相册选择立即生效，自动扫描仍要求选择至少一个相册 |
| 逐项备份 | Android 从获准访问的 MediaStore 本地图库勾选，iOS 从获准访问的 PhotoKit 本地图库勾选；两端仅保留系统部分或完整访问授权，不再提供独立选择器或导入确认页。手动备份持久化批次，消费批次不会先扫描自动相册 |
| 原始资源 | Android 将授权 URI 流式复制到私有暂存；iOS 导出获准访问资产的全部原始资源，权限或原件不可用时明确报错 |
| 下载与上传分区 | 传输页区分下载与上传；保存到手机展示字节进度、成功或失败。下载进度为当前会话观察，不宣称支持下载任务重启续传 |
| 持久化批次 | backup_batches、backup_batch_items、batch_jobs 保存来源描述和任务引用；进程中断后继续处理或说明授权/文件不可用的原因 |
| 幂等与续传 | 同来源资源、修改时间、大小的重复入队复用任务及分块；失败恢复 prepared_json、upload_id；内容变化建立独立任务 |
| 取消与共享引用 | 取消只移除当前批次的有效引用；另一个批次或自动规则仍可请求该资源 |
| 可核验回执 | 资源完成与 backup_receipts 同事务；保存服务端资产/资源 ID、BLAKE3、服务器、账户/设备和确认时间；去重路径读取资源清单 |
| 空间与重试 | 每次准备一个资产/资源并消费队列；原件与缩略图分别重试。单原件最多 2 GiB，并为分块和剩余空间预留预算 |
| 手机原件保护 | Rust 的清理仅作用于 staging/sources 内应用生成的私有副本；不删除用户原件 |
| 相册成员安全 | 手动批次不替换设备相册成员；Android 仅在完整授权、全类型、非“仅相机目录”且扫描未截断时替换，iOS 完整授权时替换，其他情况追加。两端分块请求只在首批保留替换标志，后续追加 |
| 分页云端图库 | 每页 100 项，惰性网格、asset_id 去重、重复游标拒绝；切换筛选重建分页，旧请求结果按代次丢弃 |
| 查看与保存分开 | 私有图片缓存、缩放与左右切换；保存到系统照片库是单独动作，需要相应写入权限 |

## 本地图库

| 要求 | 实现 |
|---|---|
| 完整本地目录 | Android MediaStore、iOS PhotoKit 建立全量轻量元数据目录，当前筛选的全部项目连续滚动，无手动“加载更多”。网格按日期预分组，稳定来源 ID 保留刷新后的滚动位置 |
| 按需加载 | 原生惰性网格只创建屏幕附近单元格；回执和来源详情按可见范围预取，缓存上限 768 项。Android 缩略图按实际显示尺寸解码，32 MiB LRU 缓存、最多 3 个解码任务；iOS 使用 PHCachingImageManager 预热附近项目，并取消离屏图片请求 |
| 本地增量刷新 | Android 依据 MediaStore 版本与变更编号跳过无变化扫描，只更新变更元数据并核对删除 ID；iOS 应用 PhotoKit 增删改通知。首次建库、权限范围变化、版本重置或无法获得增量时完整重建，不改变既有备份回执和排除规则 |
| 权限变化 | 区分完整、部分、无访问；返回前台重读授权范围，监听 MediaStore / PhotoKit 变更自动刷新。权限撤销只改变本地可见性，不传播为云端删除 |
| 布局与缩放 | 本地顶部仅按钮固定，透明背景允许照片滚动经过；日期正常滚动；双指缩放范围为每行 1～8 张；选择模式的全选和取消位于右侧 |
| 筛选与选择 | 相册、照片/视频、未备份/待确认筛选；按日期分组；长按选择、预览后选择、日期全选与“选择当前筛选全部项目” |
| 选择统计 | 按照片/视频资产计数；Android 汇总 MediaStore 大小。PhotoKit 没有公开的全资源大小字段，iOS 明示准备时确认，避免为估算提前导出全库 |
| 本地来源 | 自定义图库复用自动扫描的稳定来源 ID/版本；Android 使用获准访问的 MediaStore URI，iOS 使用获准访问的 PhotoKit 资产身份；历史队列中的导入别名继续兼容 |
| 可信角标 | source_resource_sets 声明原始资源数量；必须收到全部原始资源回执才能判定完整，原件完成但缩略图失败单独显示。没有证据显示“状态待确认” |
| 云端状态变更 | 完整图库缓存建立后核对回执对应资源是否仍存在；云端永久删除或资源被替换后回到待确认，并包含在未备份/待确认筛选中 |
| 自动排除 | 单项“不再自动备份”持久化到 automatic_exclusions，停止自动引用；再次手动选中仍可上传，与“取消本次上传”分开 |
| 云端浏览缓存 | 图片内存缓存 24 MiB，下载/解码并发 3；磁盘默认 256 MiB，可设置 64–1024 MiB并清空。清理不触碰上传暂存或系统照片 |

iOS 本地目录按当前选定的 PhotoKit 相册重建元数据视图，避免把一个资产错误地认定为只属于一个相册。
上传队列、回执和自动排除独立于该视图，切换相册不会清除它们。

## 增量缓存与服务端接口

| 要求 | 实现 |
|---|---|
| 真正的增量缓存 | gallery_assets、gallery_state、gallery_pages 持久化元数据和分页结果；资产事件获取最新详情后应用。详情请求仅 404 表示不存在，网络/授权错误不推进序号 |
| 原子处理 | 同一 SQLite 事务写资产变化、删除受影响分页并推进 sequence；任何事件失败回滚全部修改。空事件页保留已有分页缓存 |
| 首次快照 | 先 GET /v1/sync/head 捕获水位，再用 /v1/library/snapshot 按 UUID 升序分批走完整库（含回收站），最后消费该水位之后的事件；分页进度可以重开恢复 |
| 首屏延迟 | 时间线首屏独立加载；元数据缓存每轮最多 10 页，在图库页面后台逐步构建，每 30 秒继续/刷新，不让首屏等待全库 |
| 离线浏览 | 已保存的同账户、同查询页可离线读取，并标注“离线缓存”；未缓存的页不伪造数据 |
| 全库筛选 | 服务端时间线支持 media_kind、from_ms（含）、to_ms（不含）、device_id；两端 UI 传递服务端条件，分页与缓存键包含所有筛选 |
| 设备列表 | /v1/devices 仅返回当前账户设备；默认云端时间线仍显示整个账户 |
| 中等预览 | /v1/resources/{id}/preview 生成最长边 1600 的 JPEG，应用方向信息；服务端并发 2、解码预算 256 MiB、派生缓存 64 MiB；不改写备份原件 |
| 原件回退 | 图片格式不支持预览时返回 415，客户端在预算内读取原件，超预算保留缩略图并提示保存到手机；缩略图、预览和原件缓存键分开 |
| 视频读取 | 原始 content 接口支持单段 Range、206/416、Accept-Ranges、HEAD、ETag/If-None-Match/If-Range；流式读取字节窗口 |
| 移动在线播放 | Android Media3 + 同源 OkHttp 数据源；iOS AVPlayer + AVAssetResourceLoader，通过受控 HTTPS 分段传输，支持播放器定位，关闭/切换时取消请求 |
| 视频播放界面 | 本地视频直接进入黑色全屏预览，点击播放后开始；本地与云端共用现代播放控件，提供可拖动进度条、缓冲进度、时间显示和 0.5×–2× 倍速。播放时控件自动隐藏，点按画面再次显示；本地预览以胶囊按钮切换备份选择，后台或退出时暂停 |
| SQL 批量查询 | 时间线/快照在一个读事务里选取 ID，批量装配资产、资源和标签，查询数不随单页资产数增长；批量标签成员变更为旧/新成员生成资产事件 |

Android/iOS 的所有鉴权资源请求只接受同源 HTTPS，并禁止重定向；视频不把令牌放到 URL。
配对后的本地数据库按服务器地址与设备实例 ID 生成独立配置键，并在读取/写入云端缓存与上传前核对
服务器、账户 ID 和设备实例 ID。同实例轮换授权码复用该实例的队列；另一实例使用独立队列，绑定身份不匹配时拒绝复用。

## 版本与配套部署边界

移动状态契约为 `1.0.0` / `xszc-mobile-v1` / SQLite revision `1`，C/JNI `transfer` 提供批次和图库操作。
xcsc ABI 为 v1；配对取得设备令牌以及实际账户/设备实例 ID。
不兼容的移动数据库与队列会保留并明确拒绝，不在产品启动路径内改写。

配套服务端须支持 `/v1` 上传、筛选、快照和预览接口。协议依赖在 Cargo 清单和锁文件中固定到精确
Git revision；服务端的安装和发布按独立服务端仓库文档执行。

## 自动化验证入口

- Rust：`cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets --locked -- -D warnings`、`cargo test --workspace --locked`。
- Android：`gradle -p clients/android testDebugUnitTest assembleDebug`；系统集成验证使用 `scripts/test-android-emulator.sh`。
- C/JNI：`scripts/test-mobile-ffi-c.sh`、`scripts/test-mobile-ffi-jni.sh`。
- 移动契约与打包：`scripts/check-mobile-contract.sh`、`scripts/check-workflow-supply-chain.sh`、`python3 scripts/test-package-ios-ipa.py`。
- iOS：按[构建指南](development.md#ios)使用 Xcode 构建和运行单元/UI 测试；语法检查不能替代 Apple SDK 类型检查。

核心回归覆盖：重复选择保留分块、进程重开恢复、共享批次取消、自动引用保留、
私有副本删除后的重试、回执哈希拒绝、多资源未完成不误报、自动排除允许手动覆盖、
账户 ID 不匹配拒绝、事件中途失败不推进序号、快照游标重开和冲突、空事件保留分页。

视频 UI 验收使用合成的 12 秒 H.264 素材，覆盖全屏尺寸、默认暂停、进度定位、播放推进、倍速切换、备份选择和后台暂停。
iOS 通过 `scripts/seed-ios-ui.sh` 导入与 Android 相同的视频素材，再运行 `NavigationTests`；Android 用例位于 `GalleryNavigationInstrumentedTest`。

本地目录回归使用 10,003 项元数据验证全量索引、日期分组、类型/相册/备份筛选、跨原分页边界的详情查询，以及增量删除后保留备份排除规则。Android/iOS UI 用例使用超过 150 个系统照片资产，检查连续滚动及回到前台后位置保留；Android 同时验证新增照片自动刷新和跨屏全选。

## 设备验收

1. 关闭自动备份后只选择三张照片，确认只上传这三项及关联资源；手动视频不受自动照片规则阻止。
2. 上传中重复选择、取消一个共享批次、杀进程和重启，确认剩余任务保留分块并恢复；权限失效有明确原因。
3. 完整/部分授权切换和撤销权限；云端无需照片库权限；本地消失不触发云端删除。
4. 数万项本地图库检查首屏、连续滚动、相册/日期/类型筛选、跨屏全选、新增/修改/删除后的刷新和位置保留；云端检查持续分页、设备切换、离线已缓存页、同步后刷新和账户切换不串图。
5. iOS Live Photo、RAW 配对和编辑资产检查所有原始资源；选择器导入副本不宣称等同完整资产。
6. 原件成功、缩略图失败只重试关联资源；自动排除后仍可通过手动选择上传。
7. 大图缩放和平移、视频封面、开始播放、快进/拖动定位、弱网中断、退到后台、关闭播放器和切换账户时释放网络连接。
8. 清空浏览缓存不删除上传暂存；设置预算后检查磁盘占用；保存到手机与打开查看严格分开。

正式发行版本检查要求已存在、指向 HEAD 的发行标签以及干净 checkout。
自动化检查结果以对应提交的 CI 为准。系统后台调度、实机触控和视频解码兼容性需要真机验收。
应用不提供人脸识别、AI 分类、共享相册或复杂编辑。

## iOS IPA 交付

普通 CI 与正式 Release 通过 `scripts/package-ios-ipa.py` 输出
`xszc-ios-<版本>-unsigned.ipa`，内部为标准 `Payload/Xszc.app`，保留可执行权限、资源和包内符号链接。
IPA 未配置 Apple 发布签名，需要自行签名后安装。

打包测试使用临时测试包，验证 ZIP 布局/资源/权限和对模拟器包、错误版本/应用 ID、缺失二进制及越界符号链接的拒绝；
打包测试验证归档合同；实际 iOS 安装包由 macOS 工作流构建后生成。
