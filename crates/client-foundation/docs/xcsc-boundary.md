# xcsc 与产品边界

Ana 通过本地路径编译 `crates/client-foundation` 下的 xcsc。客户端主仓库管理该源码和工作区锁文件。

客户端使用 `xcsc::log` 获取结构化事件、UTC 时间、脱敏和有界日志查询/输出，日志层为 `xcsc::log::XcscStructuredLayer`。xcsc 也提供 Linux 离线维护功能，由需要该能力的工具显式启用。

| 所属 | 应负责 | 不应负责 |
|---|---|---|
| xcsc | 桌面、移动及离线客户端的运行时、Spool、文件与秘密安全、便携日志、原生终端输入、服务生命周期、本机只读状态通道和移动 FFI | 产品登录协议、远端 API 状态解释、产品错误码及恢复文案、本机第三方服务策略和管理服务端的 Web |
| 产品仓库 | 业务 DTO、端点、状态机、错误码、恢复步骤、业务页面、业务安全加强和产品发布验收 | 复制 xcsc 已发布的实现并维护第二事实源 |

公共实现应当满足以下条件。

1. API 用平台概念表达，不包含 xsos、xscs、xcos、ana-server 等产品名称或业务 DTO。
2. xcsc 可以独立测试它，不需要启动某个产品的协议端点或读取产品状态。
3. 产品仍能在适配器前后施加更严格的安全规则；公共实现不会把最强产品规则降成最低共同标准。
4. 根据职责和通用性决定归属。产品业务规则由各产品维护。
5. Ana 的消费者通过工作区内的同一个 xcsc 包使用公共实现。

终端输入 API 处理控制终端、输入上限、绝对期限和秘密清零，可由多个桌面客户端复用。产品提供登录请求的 HTTP 语义、提示和恢复步骤。`xcsc::cli` 提供稳定错误信封，并通过 `ProductErrorCatalog` 接收产品展示信息。

能力配置也不能把某个产品架构冒充通用要求。`desktop-client` 只要求产品提供 HTTPS 投递适配器；Spool、xcsc 私有状态、Doctor、完整服务生命周期和受保护终端输入均按实际采用情况显式声明。实时流客户端根据实际采用的机制声明能力。

通用机制还必须由实际层级承载。`xcsc::secure_xml` 提供客户端侧与产品无关的解析预算；业务 XML 协议、命名空间、设备字段和具体预算值由产品定义。


xcsc 在 Ana 工作区内是一个 Cargo 包。消费检查解析工作区继承、别名和所有 Cargo 清单，并核对唯一 xcsc 包、精确版本和本地来源。检查覆盖各目标平台依赖及 Cargo `patch`/`replace`，`source_roots` 只限定源码扫描入口。

`Args::parse` 解析通用选项以及产品显式声明的选项，仅为通用 `--config` 验证绝对路径。产品选项的含义与路径要求由产品在命令执行前检查，可复用 `absolute`；xcsc 不依据产品选项名推断业务语义。

CLI 输出经过递归脱敏：字段名大小写和连接符不影响匹配，密码、令牌、凭据、证书及 API/私钥字段中的字符串、数字、对象或数组会整体替换为 `{"configured": boolean}`；布尔值保留，供状态标志使用。普通字符串和人类可读输出中的字段名会移除控制字符。产品应使用明确的字段名表达秘密，并且不得将秘密放入普通字段或错误详情中。
